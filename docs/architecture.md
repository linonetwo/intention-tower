# 当前架构

核对日期：2026-11-05。本文描述现有代码；设计目标见 `design/`，待办见 `todo.md`。

## 主链路

```text
React 场景／图谱／操作
  → Zustand 操作与前端快照
  → tauriApi：桌面 invoke 或浏览器 MCP
  → Rust 命令校验与队列
  → SimulationRunner 顺序执行系统
  → WorldState、事件、关卡进度
  → 前端读取新快照并呈现
```

Rust 是唯一的规则权威。浏览器试玩也连接真实 Rust 核心，不是另一份
JavaScript 模拟。桌面外壳使用 Tauri；网页试玩需要同时运行核心服务。

## 主要设计模式

| 模式 | 现有实现 | 边界 |
|---|---|---|
| 集中世界状态与顺序系统管线 | `WorldState` 保存实体和进度，`SimulationRunner` 按固定顺序调用 `System::run` | 不是严格 ECS；系统共享可变状态，顺序影响语义 |
| 命令队列 | 操作校验后入队，由命令系统结算 | 暂停时等待单步；运行时操作会触发零时长 tick |
| 事件通知与快照 | 事件用于反馈、学习及进度；UI 读取权威快照 | 不是事件溯源；不能仅靠事件日志重建世界，也没有完整 CQRS 分离 |
| 平台适配器 | `tauriApi` 封装 Tauri IPC 和浏览器 MCP | 同一核心规则，两套传输与存档入口 |
| 数据驱动关卡 | 关卡资源定义角色、命令、目标、房间及连接 | 新规则仍需明确的 Rust 效果和判据，不能只靠按钮计数伪装完成 |
| 组合式角色 | 头部、躯干、四肢与服装共享骨架和姿势函数 | 人形共享关节采样；动物以步态帧和身体形变表达相同动作语义 |
| 短期动作归约与共享播放器 | `acceptWorld` 将新快照和本次事件归约为角色当前 `SceneMotion`，共享 RAF 驱动位移和姿态 | 动作只服务呈现，不写入存档；世界结果继续由 Rust 决定 |

## 场景与图谱

场景目前由 React DOM/CSS 和局部 SVG 渲染，不是 Pixi。纸娃娃使用分层图片
与关节旋转，站坐、步态、攀爬及交互共用动作采样，服装只替换部件。
动物复用已有步态帧、站坐素材和动作形变，非人形使用对应身体表现。
场景数据描述房间、地面、平台
和连接通道；移动由核心约束，普通点击只选择横向目标。

心智图谱由 React SVG 渲染；`d3-force` 仅计算布局，不使用 D3 操作 DOM。
图谱是角色实际心智状态的视图，不是独立的规则数据库。

房间记忆和梦境层级是场景的可选能力。梦境保存角色自己的当前层、返回位置、
观察及行动记录，跨层不替换角色或清空其心智。真实进食与虚拟奖励是不同效果。

动作归约按本次结果确定优先级：位移／连接器、姿态、实际进食或受击、
主要行为、一般正反馈。自主选择消费执行事件，先天反射消费动作节点的激活事件，
持续快照不重复播放。位移在世界坐标中插值，镜头变化只改变投影；
中断从当前显示位置和姿态接续，换装保持动作。连接器使用显式入口组成两段路径：
先水平走到入口，再沿连接器上下移动。读档及角色跨层清理旧动作。

## 存档与验证边界

存档保存完整 `WorldState` JSON。读取时校验并结合关卡配置恢复；浏览器保存
在本地存储，桌面使用文件。事件日志也在状态内，不是外部消息总线。

测试职责分开：Rust 验证规则与因果结果，UI 测试验证呈现和交互状态，
真实浏览器只保留关键桌面／手机旅程、素材和布局检查。通关脚本通过不等于
所有 Wiki 设计已经完成，也不等于移动设备真机或商店发行验收。

## 当前主要负担

- 系统共享可变世界，依赖执行顺序；运行时操作触发整条零时长管线。
- 完整快照与持续增长的事件日志增加传输、存档成本。
- Rust／TypeScript 数据契约手动维护；桌面与网页存档入口需要保持一致。
- `GameScene` 集中了投影、房间能力、移动和界面职责；还有未使用的 Pixi 依赖。

后续重构围绕具体问题直接删除或收拢旧实现，不预先引入新的框架、插件总线
或另一套状态管理。待办只保存在 `todo.md`，完成结果记录于日期工作日志。
